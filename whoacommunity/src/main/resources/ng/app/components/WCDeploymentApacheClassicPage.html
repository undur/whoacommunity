Deploying with Apache and mod_WebObjects reference draft

The classic, published for comparison — the field-tested guide is Pure Modulo. See also Apache with modulo, the hybrid.

WebObjects deployment as it has been done since the last century: Apache on 80/443 with a compiled mod_WebObjects module, certbot certificates, wotaskd and JavaMonitor managing instances. Read it beside the pure-stack guide and notice what appears here that doesn't exist there:

  • a C toolchain and an Apache module build, on a production server
  • the split install — every app's (and framework's) WebServerResources copied into Apache's docroot, again on every deploy
  • per-vhost rewrite maintenance, applied by reload
  • one certbot run per hostname, now and forever, plus a second renewal machinery with its own timer

And what doesn't appear because it can't: WebSocket proxying (mod_WebObjects predates WebSockets), hot config reload, or a certificate that arrives because you added a hostname to a file.
