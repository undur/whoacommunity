Setting up a deployment server with modulo work in progress

Under active development — the guide and the script it renders change frequently.

The guide below is the setup script — setup-server.sh from the modulo repository, with its comments as the explanation column. It requires git, maven and a JDK on your workstation, and root ssh access to the server. Run it against a fresh server and it:

  • builds the three bundles locally — wotaskd, JavaMonitor and modulo
  • installs a JDK on the server if missing, and creates the /opt/webobjects layout
  • creates a dedicated unprivileged webobjects user — the install runs as root over ssh, but everything runs as this user (modulo binds 80/443 via AmbientCapabilities, and apps launched by wotaskd inherit it too)
  • writes modulo's config with the server's own hostname as the first site
  • installs systemd units and log rotation, and starts the stack

What lands on the server:

/opt
├── jdk-<version>/     the JDK — distribution and version per your choice
└── webobjects/
    ├── apps/          the stack's own .woa bundles: wotaskd, JavaMonitor, modulo-runner
    ├── conf/          SiteConfig.xml — wotaskd's config store (the daemon writes here)
    ├── log/           one log per service…
    │   └── access/    …and per-site access logs
    ├── acme/          ACME account key + issued certificates
    └── modulo.toml    modulo's root config — sites, admin, wotaskd, certs

A revised default layout — per-app homes, sites as files, a stack directory — is under design: DEFAULT-DIRECTORY-STRUCTURE.md. Opinions welcome.

A few minutes later the server serves its own admin dashboard over a real certificate, ready for apps.

curl -O https://raw.githubusercontent.com/undur/modulo/main/scripts/setup-server.sh
chmod +x setup-server.sh
./setup-server.sh myserver.example you@example.com
