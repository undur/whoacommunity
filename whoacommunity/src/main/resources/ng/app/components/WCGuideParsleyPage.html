Parsley template syntaxa reference, Parsley 1.6

Parsley is the template parser for WebObjects components. It reads the inline tag syntax that WOOgnl introduced, <wo:str value="$name" />, as well as the classic <webobject> tags with a .wod file, and adds the things a parser written this century should have: line and column numbers in errors, errors shown in the page during development, and a few directives. It is built on the template parser from ng-objects, so ng-objects templates use exactly this syntax too. wonder-slim includes and enables it; in a classic Wonder or plain WebObjects project, add the is.rebbi.parsley:parsley dependency and call Parsley.configure().register() in your Application's constructor. The README has the configuration options.

This page is the syntax. If you know WOOgnl you can skim to binding values and directives, where the differences are.

1. Dynamic tags

A dynamic element is written as a tag in the wo namespace, with its bindings as attributes:

<wo:WOString value="$person.name" />

<wo:WOHyperlink action="$selectPerson" class="row">
    <wo:WOString value="$person.name" />
</wo:WOHyperlink>

The part after the colon is the element or component name, resolved exactly as WebObjects resolves it: a dynamic element class, a component in your project or a framework, or one of the shortcuts below. Case matters. A tag with children needs a closing tag that matches; a tag without content is self-closed with />. Tags in any other namespace, svg:rect or xsl:template, are left alone as ordinary HTML.

2. Binding values

One rule decides everything: an inline value that starts with $ is dynamic, anything else is a constant string. The quotes around an attribute are only delimiters; they don't mean "string" the way they do in a .wod file.

WrittenMeaning
value="$person.name"A key path, evaluated against the component with key-value coding. Read and, where the element pushes values back, written.
value="Hello"The constant string Hello.
condition="$true" negate="$false"Boolean constants. Exactly $true and $false, lowercase; WOOgnl accepted any case, Parsley doesn't.
maxLength="$40" step="$0.5"Numeric constants. A dynamic value that parses as a number is a number, not a key path.
value="$^title"A parent binding: whatever the component using this component bound to its own title. The classic pass-through, for wrapper components.
condition="$!person.isActive"Negation. The key path is evaluated and its truth inverted: null, false and a number that is exactly zero are false, everything else is true. Read-only.
disabledA valueless attribute is a binding set to true. Handy for HTML-style flags on elements that expect a boolean.
value="~person.name.toUpperCase()"An OGNL expression, when the optional parsley-ognl module is installed and its association factory registered. Anything not starting with ~ falls through to the rules above.

Constants can carry escapes: \n, \r, \t, \\, \", and \$ for a literal dollar sign at the start of a value. Attribute values may also be unquoted when they contain no spaces, value=$name, though quoting is the convention. Writing the same binding twice on one tag is an error; WOOgnl silently kept the last one.

3. Conditionals and repetitions

<wo:if condition="$person.isActive">
    Active since <wo:str value="$person.activeSince" dateformat="%Y-%m-%d" />
</wo:if>
<wo:else>
    Inactive
</wo:else>

<wo:if condition="$people.count" negate="$true">Nobody here.</wo:if>

<ul>
    <wo:repetition list="$people" item="$person" index="$index">
        <li><wo:str value="$index" />. <wo:str value="$person.name" /></li>
    </wo:repetition>
</ul>

wo:if takes condition and an optional negate. A wo:else immediately after it renders when the condition was false. $!key and negate="$true" do the same job; use whichever reads better. wo:repetition takes list and item, with optional index and count; the item and index are pushed into the component's fields on each pass, so they must be settable.

4. Generic elements and component content

When you want a plain HTML element with a dynamic attribute, use a generic container or element and name the tag with elementName. Bindings that aren't the element's own are written out as attributes:

<wo:container elementName="li" class="$rowClass">…</wo:container>
<wo:element elementName="link" rel="stylesheet" href="$stylesheetURL" />

A component that wraps content, a page layout for instance, places <wo:content /> where the caller's content goes.

5. Directives

Two tags in the p namespace speak to the parser rather than to WebObjects:

<p:raw>
    <script>if (a < b && c) { render("<wo:notatag>"); }</script>
</p:raw>

<p:comment>
    A note for the next developer. Nothing between these tags reaches the browser.
</p:comment>

p:raw passes its content through untouched, so script blocks and anything that could look like a tag are safe. p:comment is stripped entirely from the output. Both nest. Ordinary HTML comments, <!-- -->, are not special to Parsley any more: they flow through to the browser like any other markup, and dynamic tags inside them are still evaluated, so use p:comment for anything you mean to hide.

6. Bundle templates and .wod files

The traditional form still works, alone or mixed into the same template as inline tags: a named placeholder in the HTML and a declaration in the component's .wod file.

<webobject name="PersonName" />
<webobject name="Rows">…</webobject>
PersonName : WOString {
    value = person.name;
    escapeHTML = true;
}

Rows : WORepetition {
    list = people;
    item = person;
}

In a .wod file the rule is the classic one: a quoted value is a constant string, an unquoted value is a key path, with true, yes, false, no, nil and null read as booleans in any case, and numbers as numbers. ^ and ! work as they do inline. Comments are /* … */. Declaring the same name twice, or a placeholder with no declaration, is an error with a line number.

7. Tag aliases

The shortcut table is data, not code. Every parsley-tag-aliases.properties on the classpath is loaded and merged, each line alias = target, and resolution is recursive: str goes to WOString, and if a framework has declared WOString = ERXWOString, on to that. A framework or an application can add its own shortcuts, or replace an element class everywhere, by dropping the file into src/main/resources:

# parsley-tag-aliases.properties
WOString = ERXWOString
widget = com.example.MyWidgetElement

If two files map the same alias to different targets, the first registration wins and the conflict is logged, rather than depending on classpath order.

8. Errors, in the page

In development mode Parsley reports problems where you're looking. A tag that names an element or component that doesn't exist, a key path that can't be resolved, a binding an element rejects, a duplicate attribute, or a malformed tag like <wo: Repetition> with a space after the colon: each shows as a message in the rendered page with the template's line and column, instead of an exception page. Exceptions thrown while rendering or invoking an action carry the same source location. The in-page controls strip in the bottom-left corner toggles these features at runtime. In production both are off and errors behave as they always did.

9. If you're coming from WOOgnl

  • OGNL expressions need the parsley-ognl module; they are not built in.
  • $true and $false are case-sensitive.
  • Duplicate bindings on a tag fail instead of being silently overwritten.
  • HTML comments are no longer parsed specially; use p:comment to hide things.
  • WOOgnl's parseStandardTags mode and tag processors such as <wo:not> are not supported.
  • The editor side, completion and validation of all of the above, is Parslips, which reads build.properties for the inline binding prefix; the default is $.
